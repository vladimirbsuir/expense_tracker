## Введение

Данный документ описывает план тестирования приложения ["Expense Tracker"](https://github.com/vladimirbsuir/expense_tracker). Документ предназначен для людей, выполняющих тестирование данного проекта. Цель тестирования - проверка соответствия реального поведения программы проекта и ее ожидаемого поведения, которое описано в [требованиях](https://github.com/vladimirbsuir/expense_tracker/docs/SRS.md).

<a name="items"></a>

## Объект тестирования

В качестве объектов тестирования можно выделить следующие функциональные требования:

* Создание расходов/доходов;
* Создание напоминаний;
* Управление ранее созданными расходами;
* Фильтрация расходов/доходов;
* Экспорт и импорт данных;
* Корректное отображение графиков расходов;
* Появление сообщений, создаваемых напоминаниями.

<a name="quality"></a>

## Атрибуты качества

1. Функциональность:
    - функциональная полнота: приложение должно выполнять все заявленные функции;
    - функциональная корректность: приложение должно выполнять все заявленные функции корректно;
2. Удобство использования:
    - все функциональные элементы пользовательского интерфейса имеют названия, описывающие действие, которое произойдет при выборе элемента.

<a name="risk"></a>

## Риски

В данном случае к рискам можно отнести:
* некорректный учет расходов и доходов, из-за чего графики не будут соответствовать фактическим показателям;
* отсутствие срабатывания напоминаний, из-за чего пользователь не сможет вовремя реагировать на требуемые события.

<a name="features"></a>

## Аспекты тестирования

В ходе тестирования планируется проверить реализацию основных функций сервиса. Аспекты, подвергаемые тестированию: 
* Авторизация в сервисе;  
* Создание/удаление/изменение расходов;
* Создание/удаление/изменение доходов;
* ЭКспорт/импорт расходов/доходов;
* Фильтрация расходов/доходов по категориям;
* Отображение графиков и баланса;
* Выход из сервиса.

### Авторизация в сервисе

Этот вариант использования небходимо протестировать на:
* осуществление входа в сервис либо регистрацию, если пользователь использует сервис впервые;
* отображение страницы согласно [mockup](https://github.com/vladimirbsuir/expense_tracker/docs/moqups/auth.png).

### Создание/удаление/изменение расходов

Этот вариант использования небходимо протестировать на:
* создание расхода;  
* изменения информации о расходе;
* удаление расхода.

### Создание/удаление/изменение доходов

Этот вариант использования небходимо протестировать на:
* создание дохода;  
* изменения информации о доходе;
* удаление дохода.

### Экспорт/импорт расходов/доходов

Этот вариант использования небходимо протестировать на:
* экспорт имеющихся расходов и доходов;
* импорт имеющихся расходов и доходов.

### Фильтрация расходов/доходов по категориям

Этот вариант использования небходимо протестировать на:
* фильтрация расходов/доходов для отображения только тех, которые относятся к выбранной категории

### Отображение графиков и баланса

Этот вариант использования небходимо протестировать на:
* отображение графиков на основе имеющихся расходов
* изменение графиков при удалении/модификации расходов
* подсчет баланса на основе имеющихся данных о расходах и доходах

### Выход из сервиса

Этот вариант использования небходимо протестировать на:
* завершение пользователем текущей сессии и возвращение к страницы авторизации.

## Нефункциональные требования:
* время ответа сервиса составляет менее 1.5 секунды;
* сервис доступен 99.9% времени;
* сервис может выдерживать более 100 одновременных пользователей.

## Выводы

Данный тестовый план позволяет протестировать основной функционал сервиса. Успешное прохождение всех тестов не гарантирует полной работоспособности в различных реальных ситуациях, однако позволяет полагать, что данный сервис работает корректно в большинстве случаев и удовлетворяет ожидания пользователей.
